# Cognia Browser Companion

[English](README.md) · [Cognia 主仓库](https://github.com/MaxQian888/cognia-next) · [官网仓库](https://github.com/cognia-labs/cognia-website)

面向 Chrome 和 Edge 的侧边栏插件：把正在阅读的页面发送给 Cognia，也可按需允许 Cognia 代理操作浏览器。本仓库独立维护完整插件、测试和发布压缩包。

## 安装与升级

从 [Releases](https://github.com/cognia-labs/cognia-browser-extension/releases) 下载 Chrome 压缩包并解压，在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的目录。需要 Chrome 116 或以上。仓库发布不会自动提交到插件商店。

在 Cognia 中启用 Browser Access 并创建 Browser Companion 配对码；打开插件侧边栏，粘贴配对码并同意可选的本机回环地址权限。配对协议、设备密钥、来源绑定和浏览器存储标识保持兼容。

升级已解压插件时，保留原目录并点击“重新加载”。目录变化会改变 Chrome 派生的插件 ID，需要重新配对。商店版更新必须保留原有签名和商店身份。

## 功能

- 一次可选取多个元素：Shift、⌘ 或 Ctrl 点击可增减单个元素，Alt 点击会选中所有相似元素（相同标签和类名），在页面上拖出选框则会选中框内的控件、标题、文字和图片，拖动时实时预览。已选元素会带编号保持标记，按回车、点“完成”或最后一次普通点击即可全部添加。选取两个及以上元素时，侧边栏会比较它们的计算样式，列出不同的属性并标出不一致的值，也可以把这张表随任务一起发送。每个选取可折叠为一行，显示组件、备注和修改状态，折叠时也能直接定位或移除；批量添加的选取默认折叠，单个选取默认展开。
- 键盘焦点检查会把 Tab 顺序画成带编号的停靠点，并用依次绘出的弧形箭头连接；向页面上方回跳的箭头显示为红色虚线，存在问题的停靠点也标为红色。
- 页面选取更灵动：高亮框随指针在元素之间平滑滑动，并贴合元素圆角；选中时先以绿色脉冲确认再淡出（不会出现在截图中；系统开启“减少动态效果”时不播放动画）。新的选取、测量和附件以过渡动画进入侧边栏；整页采集的长文本保留在可滚动的框内并显示字数和行数，可点击“展开更多”。
- 侧边栏按卡片组织：采集、检查与编辑、页面工具、页面审计、最近任务和设置，每张卡片都标明用途；检查工具以磁贴形式展示，并标出正在运行的工具。配色跟随 Cognia 的外观设置。
- 捕获页面、正文或选区，生成可编辑 Markdown，保留元数据和支持的字幕。
- 添加截图、区域裁剪和其他页面；选择 Host 的投递目标并跟踪状态。
- 在页面上为代理选取元素：每个选取包含唯一选择器、角色与文本、计算样式、父级布局、截图，以及 React、Vue、Svelte、Angular 开发构建下的组件链和源码位置。可在页面上实时试改样式和文案，并以修改前后对比的请求发送。
- 复现问题时记录控制台、页面请求以及你的操作步骤（点击、按键、表单提交、页面跳转，不记录输入内容）并附加报告；将设计稿导出图叠加在页面上对比（不透明度、偏移、差值混合），并量化差异——可见页面与设计稿逐像素对比，给出差异占比、差异区域和高亮差异图（作为附件发送）；以手机、平板、笔记本和桌面视口尺寸打开页面；以及模拟页面自身的请求（参考 Requestly）——让匹配的 fetch、XHR 和 beacon 请求失败、返回指定的状态码、响应头和响应体、修改服务器的真实响应（合并 JSON、替换状态码和响应头）、延迟或改发到其他地址；可按 URL 片段、`*` 通配符或 `/正则表达式/` 匹配，提供一键预设（离线、慢速、服务器错误、空列表、未登录、不稳定），可限制只命中前几次或按概率触发，规则可暂停。规则默认在页面刷新前有效，开启“刷新后保留”后会在该标签页中于页面脚本运行前恢复（此时才请求该站点的权限）；拦截到的请求会实时记录，发送内容会注明哪些请求是模拟的，以免把模拟的失败当成后端问题。
- 在页面上悬浮显示工具：可拖动、可收起的浮动工具栏（参考 VisBug、UiToolbar），可直接选取元素、测量间距、调整最近的选取、编辑页面文字以及截图标注，效果与侧边栏中的对应按钮完全一致，侧边栏打开期间一直可用。工具栏本身不会被选取、检查、录制，也不会出现在截图中。拖到页面顶部或底部边缘时会自动变为横向并停靠在该边；无论页面如何缩放，工具栏在屏幕上的大小保持不变。页面放大（浏览器缩放或触控板捏合）且内容超出可视区域时，会自动显示小地图：以线框形式呈现整页内容，框出当前可见区域并标出已选取的元素，点击或拖动小地图即可滚动到对应位置；也可以随时在工具栏上手动显示或隐藏小地图。自动吸附为可选功能，在侧边栏悬浮栏磁贴下方开启：开启后松开悬浮栏会滑到较近的一侧（靠近中间时竖向居中），停靠在顶部或底部时吸附到左右两端或居中，并在窗口尺寸或缩放变化时保持贴边。
- 按住 Shift 点击可一次选取多个元素；开发构建下的选取还会带上组件 props 和 state（React 按调用顺序列出的 state hooks 或类组件的 state，Vue 的 data 与 setup 状态），敏感字段已脱敏。可将审阅后的上下文复制为一段提示词用于其他工具，或保存为 Markdown 文件。
- 测量页面元素间距：先后点击两个元素，即可在页面上看到以 CSS 像素标注的间距；若一个元素包含另一个，则显示四个方向的内边距，并提示差几像素未对齐的边缘。按住 Shift 点击可继续从同一元素测量；"显示并重新测量"可在预览修改后重新读取数值。每条测量都可附上期望值备注。
- 发送前标注截图：方框、箭头、画笔和编号标记，四种颜色，支持撤销。标注会绘制进图片，编号标记的备注同时以文字发送；"标注屏幕"会截取可见区域并直接进入标注，再次标注时从原始截图开始。
- 选取元素时会显示每个外边距和内边距的像素值以及元素字体。"编辑文字"可直接在页面上修改文字（Design Mode）；"完成编辑"会把每处修改整理为修改前 → 修改后，交给代理在源码中修改；"撤销全部修改"借助浏览器自身的撤销还原页面。
- 选取的元素附带清理后的 HTML（不含表单值、事件处理器和脚本）；可将任一选取复制为 HTML 及其 CSS（包含预览中的修改）。"在页面上调整"可拖动选取元素的右边缘或下边缘调整尺寸，并用方向键微调外边距（Shift 每次 10px，Alt 减少，P 切换为内边距）；按 Enter 将结果保留为样式修改，按 Esc 还原元素。包含文字的选取会显示文字与背景的对比度及 WCAG AA/AAA 评级，并给出最接近且达标的颜色，一键作为修改应用。
- 发送前检查页面：WCAG 2.2 AA 初步检查（替代文本、名称、标签、对比度、标题层级、点击区域等），每条发现可一键转为选取；页面设计 token（颜色、字号层级、间距、圆角、阴影、CSS 变量、断点）及屏幕取色器；页面使用的技术（参考 Wappalyzer）——应用与 UI 框架、CMS 与静态站点生成器、组件库、样式方案、状态库、构建工具、工具库、统计、监控、支付、认证与托管，版本取自页面全局变量、generator 标签以及 CDN 地址和 import map 中的包版本，每项附识别依据，并统计页面加载的脚本与 CSS 体积、协议和第三方来源；以及本次访问的性能——基于浏览器自身时间线的 Web Vitals（LCP、CLS、最慢交互、FCP、TTFB、阻塞时间）、造成长帧的脚本、阻塞渲染的资源、最大与最慢的资源、第三方域名和过大的图片；以及 SEO 与链接预览——标题、描述、canonical、robots、Open Graph 与 Twitter 标签、结构化数据和标题大纲，并预览分享链接时显示的卡片；键盘焦点检查——在页面上为 Tab 停靠点标号，并找出正数 tabindex、不可见的停靠点、焦点跳回上方以及键盘无法到达的可点击元素；以及当前窗口尺寸下的布局检查——导致页面横向滚动的元素、被容器截断的文字、比例变形的图片和小于 12px 的文字，每条发现与无障碍检查一样可在页面上定位或转为选取。每项仅在保持勾选时随请求发送。
- 使用保存的指令和快捷操作，支持中英文界面与 Host 外观同步。
- 按需启用代理模式，逐站决定授权，使用实际注入的 overlay 检查页面并操作标签页。
- 立即停止或接管，明确恢复后才继续；撤权、断连、禁用和超时会取消待执行工作。

安装时不授予全站页面访问权限。页面访问、代理模式、通知、下载和 Cookie 权限由对应功能按需申请。没有静态内容脚本、debugger、原生消息或无痕窗口权限。详见 [安全与隐私](SECURITY.md)。

## 开发与验证

使用 `.nvmrc` 的 Node 版本及 `package.json` 固定的 pnpm 版本：

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm check
pnpm format:check
pnpm exec playwright install chromium
pnpm test:e2e
```

正式构建输出到 `build/chrome-mv3/`，压缩包位于 `build/`，开发构建位于 `build/chrome-mv3-dev/`。CI 验证独立安装、格式、lint、类型、全部单测、真实 Chromium 流程和压缩包内容。`pnpm test:e2e` 先打包，再测试该构建，最后逐文件确认压缩包仍是同一份字节。安装包包含项目与依赖的许可证说明和精确源码版本。

E2E 使用实际 MV3 worker、面板、Chrome API 和 overlay，对接确定性的 HTTP/WebSocket Host。流程测试仅预授予回环地址权限，因为原生权限弹窗无法自动操作；另有测试加载实际发布 manifest，校验可选权限边界。原生权限弹窗、商店签名升级和打包 Cognia Host 联合验收仍需发布验证，不能由 mock Host 测试替代。

## 代码归属

`src/` 和 `public/` 是插件实现。`vendor/` 固定共享客户端、UI 和 overlay 的源代码快照及测试，消除对主仓目录和 npm 预发布的依赖。`provenance/source.json` 记录来源版本、导入时未提交状态和逐文件 SHA-256，包括本次撤权修复。

协议和 overlay 变更需要与 Host 协同。详见 [迁移与兼容说明](docs/migration.md)。日常安装、构建和测试不读取主仓库。

发布重试会解析精确 tag、恢复中断的草稿并保留已有附件字节。不同的安装包必须使用新版本，已发布附件不会被覆盖。
